# LunexSU v1.0.0 Beta4

## 中文更新日志

Beta4 整合 SUSFS 管理、超级密钥体验、安全加固及主题与输入界面修复。仍为预发布版本，请备份并准备可靠的救援方式。

### 新功能与调整

- 新增现有 SUSFS 实现的管理界面，支持规则编辑、导入与状态查看；未知或未加载的实现保持只读，不捆绑或自动加载 SUSFS LKM 引擎。内置实现的重定向 UID 模式支持 0–4，LKM 保持 0–2。
- 超级密钥可选择加密记住并自动解锁，默认不记住；完善认证取消、并发 Shell 与临时补丁文件处理。包名、发布证书及 Core 验证仍为必要条件。
- 首页新增只读、默认折叠的 Zygisk 概览；配置、待重启、已安装与暂存版本分开显示。无法查询不等于关闭，进程存在不等于注入成功。
- 固定捆绑 ReZygisk v1.0.0、NeoZygisk v2.4、ZygiskNextNext v1.12.0，保留许可证、对应源码及双重归档校验。已安装的 NextNext 不随 APK 更新自动替换；升级流程见仓库 `docs/lunexsu-zygisk.md`。
- 同步 KernelSU 上游至 `96770dfb`，包含 Android 17 QPR3 通过 `execveat` 执行 `selinux_setup` 的 preinit 兼容修复，保留完整上游历史。

### 修复与安全

- 修复 SUSFS 原生深色主题默认文字、超级密钥错误提示颜色，以及输入页、编辑弹窗、搜索结果的键盘避让和滚动可达性。
- 修复主题下载完成后立即应用失败或误用旧版本路径的竞态；完成状态与已发布的主题路径一起提供，不依赖稍后的主题库扫描。
- 修复 MT 管理器、全局搜索等小尺寸图标预览因固定 dp 内缩导致人物过小的问题，保留桌面比例和原始图像。
- 修复大尺寸本地压缩内核的 KMI 前缀探测；仍保留原始读取和解压扫描上限。
- OTA 切槽前先完整、持久化安装完成钩子；切槽失败先恢复原槽，再清理，回滚不确定时保留恢复材料。卸载时先验证备份恢复，再清理目录。
- 加固模板和 Shell 参数边界、模块安装与配置事务、崩溃恢复、内核 hook 生命周期、SELinux 策略批处理及授权标记恢复。
- metamodule 全局链接仅在安装事务持久提交后发布，避免失败或进程中断留下指向未提交空目录的活动链接。
- 限制带特权桥接的模块 WebUI 为可信本地来源；外部可执行内容、子资源及 Service Worker 网络访问被阻断。主题元数据要求严格 JSON，payload 长度与偏移先校验再分配。
- PR 产物改为无签名、不可安装的编译验证包，不再生成或传递临时私钥。历史 PR 身份不能因重建而视为已撤销。Magica 默认拒绝临时开放网络 root adbd，显式 `--magica-allow-network` 才接受相关风险。

### 下载、验证与已知限制

- 正式附件为同一标签构建的 28 项：1 个固定发布签名 Manager APK、16 个 LKM（8 个 KMI × arm64/x86_64）、8 个平台 ksud、3 个架构 ksuinit。保持正式包名及签名；新功能使用匹配的 Beta4 Core。不要刷入 PR 编译包或本地编译夹具。
- No Root UI 演示版独立提供，不包含 root 载荷，不列入这 28 个正式附件，也不能验证真实 root、OTA 或模块兼容性。
- 发布前检查包含 Codex 复审、CI、完整架构构建及实际发布 APK 签名和附件一致性。此前本地正常版 467 项、演示版 484 项 JVM 用例无失败；Windows 跳过的一项 POSIX 参数用例已由独立主机测试覆盖。新增主题下载竞态、图标比例和输入布局回归已加入检查。
- 用户已确认测试通过，但没有据此宣称所有真机矩阵通过；自动 Android 界面用例仅编译。OTA、物理断电恢复、厂商内核卸载及全部 ROM/模块组合仍需针对性真机验证。
- **ZygiskNextNext 仍有开机失败风险，版本升级不代表修复。** 默认关闭，启用仍须救援能力确认并完整等待十秒；受影响设备不要在无可靠救援方式时尝试。内置 Zygisk 不支持 riscv64，Neo 不注入 64 位系统中的 32 位应用。
- 仅支持安全回调排空的内核运行期 hook；恢复失败时宁可阻止不安全卸载。模块原子交换要求文件系统支持，失败不会通过删除旧工作副本来绕过。主题音效仍不支持。

## English changelog

Beta4 combines SUSFS management, optional encrypted superkey remembering, a read-only Zygisk overview, security hardening and input/theme fixes. This is a prerelease: back up and prepare a reliable recovery path.

- Manage existing SUSFS implementations without bundling or automatically loading a SUSFS LKM engine. Unknown/unloaded implementations remain read-only. Redirect UID schemes follow the implementation: built-in 0–4, LKM 0–2.
- Improve superkey cancellation, concurrent Shell ownership and app-owned patch files. Remembering remains opt-in; Manager package, certificate and Core checks remain mandatory.
- Pin ReZygisk v1.0.0, NeoZygisk v2.4 and ZygiskNextNext v1.12.0 with licenses, source links and reproducible hashes. APK upgrades do not automatically replace installed companions.
- Preserve upstream history through KernelSU `96770dfb`, including Android 17 QPR3 preinit support for `execveat`-based `selinux_setup`.
- Fix native dark-theme foregrounds, input-page/dialog keyboard avoidance, scrollable actions and search-result bottom insets across the shared UI paths.
- Publish the completed theme path with download completion so immediate application does not depend on a delayed library scan or reuse a deleted revision.
- Use proportional launcher padding for small MT/global-search icon previews without replacing artwork or changing the normal desktop proportion.
- Probe bounded compressed prefixes for local-kernel KMI detection. Preserve input, allocation and decompression limits.
- Durably prepare the OTA completion hook before activating the target slot. Restore the original slot before cleanup after activation failure; retain recovery material if rollback is uncertain. Verify backup restoration before uninstall cleanup.
- Harden profile arguments, module/config transactions and crash recovery, hook teardown, SELinux batches and authorization markers. Restrict privileged WebUIs to trusted local content and require strict theme JSON and validated payload ranges.
- Publish the global metamodule alias only after durable installation commit; failed commits and process death must not expose an uncommitted empty live directory.
- PR artifacts are unsigned compile-only builds, not trusted installable Manager/Core pairs. No temporary PR private keys are generated or transferred; rebuilding does not revoke historical exposed identities. Magica requires explicit `--magica-allow-network` risk acceptance.

Release assets comprise one production-signed Manager APK, 16 LKMs, eight ksud targets and three ksuinit targets, all from the release tag. Use the matching Core. The separate No Root demo is not a root implementation or part of these 28 release assets.

Release gates include Codex review, CI, the complete build matrix and actual artifact/signature verification. Local Manager suites passed 467 normal / 484 demo cases with one Windows-only POSIX skip independently covered by host tests. User-reported testing is not a claim that every device matrix passed; Android instrumentation was compiled, not automatically run. Physical power loss, vendor unload behavior, OTA and all ROM/module combinations remain device-specific validation work.

**ZygiskNextNext can still cause boot failures.** It stays off by default, with the recovery acknowledgement and full ten-second wait. v1.12.0 is not claimed to fix affected devices. Built-in Zygisk does not support riscv64; Neo does not inject 32-bit apps on 64-bit systems. Runtime hooks and atomic directory replacement require the relevant kernel/filesystem support; unsafe teardown is not forced. Theme sound effects remain unsupported.
